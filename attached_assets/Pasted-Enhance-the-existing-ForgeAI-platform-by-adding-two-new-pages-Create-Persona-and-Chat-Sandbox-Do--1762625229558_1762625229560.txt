Enhance the existing ForgeAI platform by adding two new pages — Create Persona and Chat Sandbox.

1️⃣ Create Persona Page

Path: /create

Purpose:
Allow users to create or edit a new AI persona with name, intent, description, and example dialogues.
After saving, the persona should be stored in the database and redirect to the Chat Sandbox for testing.

Frontend Requirements

Form Fields:

Persona Name (text input)

Description (textarea)

Intent (textarea with placeholder like “Define what this persona should do…”)

Few-Shot Examples (dynamic field pairs → “User Message” and “AI Response”)

Buttons:

Save Persona → Saves data to backend via POST /api/trainers

Simulate Training → Calls /api/trainers/simulate to preview generated system prompt

Clear Form → Resets all fields

Behavior:

After saving → Redirect user to /chat/:id for that persona.

Show loading spinner during save.

Show success/error toast messages.

Form should be fully responsive (2-column layout on desktop, stacked on mobile).

Validation:

Persona Name and Intent are required fields.

Prevent empty submission.

Backend Requirements

Endpoints to Implement / Verify:

POST /api/trainers
→ Creates a new persona with fields: name, description, intent, examples, user_id.

PUT /api/trainers/{id}
→ Edits existing persona (if editing support added later).

POST /api/trainers/simulate
→ Returns an “Adaptive Prompt” preview based on provided intent and few-shot examples.

GET /api/trainers/{id}
→ Fetch persona details for edit or chat testing.

Data Model Example:

{
  "id": "uuid",
  "name": "SupportBot Pro",
  "description": "Helps users solve issues politely",
  "intent": "Assist customers with order issues",
  "examples": [
    {"user": "My order hasn’t arrived.", "assistant": "I understand. Could you share your order ID?"}
  ],
  "created_at": "...",
  "updated_at": "...",
  "user_id": "..."
}

2️⃣ Chat Sandbox Page

Path: /chat/:id

Purpose:
Allow users to test their trained persona in a live chat interface, viewing responses in Markdown format and persisting history.

Frontend Requirements

Layout:

Left sidebar (optional): Persona info (name, description, version, tokens used)

Center chat area:

Scrollable message history

Messages styled differently for user vs. assistant

Bottom input box:

Text input for user message

“Send” button

“Clear Chat” button

Behavior:

On page load → Fetch persona details (GET /api/trainers/{id})

On sending message → Call /api/chat/{id} with { message }

Display AI response dynamically with typing animation.

Save conversation persistently (reload should restore past chat).

Features:

Markdown rendering with react-markdown + remark-gfm

Token counter (optional small footer below chat)

Chat history automatically scrolls to latest message

Responsive design (full width on mobile, two-column on large screens)

Graceful empty state (“Start chatting with your persona”)

Backend Requirements

Endpoints to Implement:

POST /api/chat/{persona_id}

Accepts { message: string, session_id?: string }

Retrieves persona’s system prompt + few-shot examples

Calls OpenAI API (gpt-4o-mini or similar)

Returns:

{
  "response": "AI’s reply text",
  "tokens_used": 124,
  "message_id": "uuid"
}


Saves conversation to DB under that persona’s ID.

GET /api/chat/history/{persona_id}

Returns stored messages in chronological order (for restoring chat).

DELETE /api/chat/history/{persona_id}

Clears stored chat history for that persona (for “Clear Chat” button).

Data Model Example:
{
  "persona_id": "uuid",
  "messages": [
    {"role": "user", "content": "Hi!"},
    {"role": "assistant", "content": "Hello! How can I help you today?"}
  ],
  "timestamp": "2025-11-08T12:00:00Z"
}
